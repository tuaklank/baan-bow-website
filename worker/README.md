# baanbow-office — ระบบออกเอกสาร + ติดตามงาน สั่งผ่าน LINE OA

Worker แยกตัวหนึ่ง ผูกเฉพาะ 3 path บน `baanbow.online` **ไม่แตะ deploy ของหน้าเว็บเดิมเลย**

```
LINE OA ──▶ POST /webhook ──▶ Claude อ่านข้อความ ──▶ โค้ดคำนวณยอด/ออกเลขที่ (D1) ──▶ ตอบลิงก์ /d/<token>
Cron 08:00 น. ───────────────▶ push งานเลยกำหนด/ครบวันนี้/ครบพรุ่งนี้
```

| Path | ทำอะไร |
|---|---|
| `POST /webhook` | รับ LINE ตรวจ `x-line-signature` ด้วย Web Crypto |
| `GET /d/:token` | เอกสาร A4 พิมพ์/บันทึก PDF (token สุ่ม 32 ตัว เดาไม่ได้) |
| `GET /admin` | หลังบ้านมือถือ 5 แท็บ — **ตอนนี้เปิดสาธารณะ ยังไม่ได้กั้น** (ดูขั้นที่ 7) |

path อื่นทั้งหมดของเว็บ (`/`, `styles.css`, `/design-tool/*`, assets) ไม่ผ่าน Worker ตัวนี้

## ขั้นตอน deploy

ทำใน `worker/` ทั้งหมด

### 1. ติดตั้ง

```bash
cd worker && npm install
```

### 2. สร้างฐานข้อมูล D1

```bash
npx wrangler d1 create baanbow-office
```

คำสั่งนี้จะพิมพ์ `database_id` ออกมา — **เอาไปใส่แทน `PUT_D1_DATABASE_ID_HERE` ใน `wrangler.toml`**

### 3. สร้างตาราง

```bash
npx wrangler d1 migrations apply baanbow-office --remote
```

(ตัด `--remote` ออก = ลงฐานข้อมูลในเครื่องสำหรับทดสอบ)

คำสั่งนี้รันซ้ำได้เรื่อยๆ ลงเฉพาะ migration ที่ยังไม่เคยลง — ทุกครั้งที่มีไฟล์ใหม่ใน `migrations/` ต้องรันก่อน `deploy`

### 4. ใส่ secret ทั้ง 4 ตัว

รันทีละคำสั่ง แล้วพิมพ์ค่าตอนที่มันถาม (ค่าไม่ถูกเก็บลง git และไม่ขึ้นบนหน้าจอ)

```bash
npx wrangler secret put LINE_CHANNEL_SECRET
```

```bash
npx wrangler secret put LINE_CHANNEL_ACCESS_TOKEN
```

```bash
npx wrangler secret put ANTHROPIC_API_KEY
```

```bash
npx wrangler secret put ALLOWED_USER_IDS
```

- `LINE_CHANNEL_SECRET` / `LINE_CHANNEL_ACCESS_TOKEN` — จาก LINE Developers Console แท็บ Messaging API
- `ANTHROPIC_API_KEY` — จาก console.anthropic.com
- `ALLOWED_USER_IDS` — userId ของเจ้าของ คั่นด้วย `,` **ยังไม่รู้ให้ข้ามไปก่อน** แล้วทำขั้นที่ 6

`CLAUDE_MODEL` ไม่ใช่ secret อยู่ใน `[vars]` ของ `wrangler.toml` ค่าเริ่มต้น `claude-sonnet-5-5`

### 5. deploy

```bash
npx wrangler deploy
```

ครั้งแรก wrangler จะถามว่าจะสร้าง route ให้ไหม — ตอบ yes
ถ้าสร้างไม่สำเร็จ หรืออยากตั้งเอง ไปที่ Cloudflare dashboard → Workers & Pages → `baanbow-office` → Settings → Domains & Routes → Add route แล้วใส่ครบ 6 เส้น:

```
baanbow.online/webhook          www.baanbow.online/webhook
baanbow.online/d/*              www.baanbow.online/d/*
baanbow.online/admin*           www.baanbow.online/admin*
```

> **ทำไม 6 เส้น** — `baanbow.online` กับ `www.baanbow.online` เสิร์ฟ 200 ทั้งคู่ ไม่ redirect หากัน ถ้าผูกแค่ apex แล้ว LINE ยิง webhook มาที่ `www` จะตก 404 เงียบๆ
>
> **ชนกับเว็บเดิมไหม** — ไม่ชน เว็บเดิมคือ Worker ชื่อ `baan-bow-website` ผูกแบบ **Custom Domain**
> (หน้า Workers Routes ของโดเมนว่างเปล่า) ซึ่ง Cloudflare ระบุว่า route **ชนะ** Custom Domain บนโฮสต์เดียวกัน
> → 3 path นี้เข้า Worker ใหม่ ที่เหลือยังไปที่ `baan-bow-website` เหมือนเดิม
> ดู "Interaction with Routes" ใน <https://developers.cloudflare.com/workers/configuration/routing/custom-domains/>
>
> route ต้องการให้โฮสต์นั้นมี DNS record แบบ proxied อยู่ก่อน — Custom Domain สร้างให้แล้วทั้งสองโฮสต์ ไม่ต้องทำอะไรเพิ่ม

### 6. ตั้ง LINE webhook แล้วหา userId

1. LINE Developers Console → Messaging API → **Webhook URL** = `https://www.baanbow.online/webhook` → กด Verify → เปิด **Use webhook**
2. ปิด **Auto-reply messages** กับ **Greeting messages** ไม่งั้นบอทจะตอบทับ
3. ทักบอทในแอป LINE ครั้งแรก — ถ้ายังไม่ได้ตั้ง `ALLOWED_USER_IDS` บอทจะตอบ userId ของคุณกลับมา
4. เอา userId ไปใส่: `npx wrangler secret put ALLOWED_USER_IDS` แล้ว `npx wrangler deploy` อีกครั้ง

หลังจากนี้คนอื่นที่ไม่ได้อยู่ในรายการสั่งงานไม่ได้ และบอทจะไม่ตอบอะไรเลย

### 7. กั้น /admin ด้วย Cloudflare Access (ยังไม่ได้ตั้ง — เลือกไว้แบบนี้)

> **สถานะจริง ณ 19 ต.ค. 2569: ยังไม่ได้ตั้ง Access** `/admin` ตอบ 200 ให้ทุกคนที่รู้ URL
> เป็นการตัดสินใจของเจ้าของ ไม่ใช่งานที่ลืมทำ · หน้ามี `noindex, nofollow` อยู่แล้ว Google จึงไม่เก็บเข้าดัชนี
> แต่ใครเปิด `/admin` ได้ก็เห็นลิงก์ `/d/<token>` ของเอกสารทุกใบ ซึ่งมีชื่อ ที่อยู่ และเลขผู้เสียภาษีของลูกค้า
> เปลี่ยนชื่อ path แทนการกั้นไม่ช่วย เพราะ route อยู่ใน `wrangler.toml` ที่ push ขึ้น repo สาธารณะ

Worker ตัวนี้ **ไม่มีระบบ login ของตัวเอง** ตั้งใจให้ Access กั้นจากข้างนอก ถ้าไม่ตั้ง = ใครก็เปิดดูได้

Zero Trust → Access → Applications → Add a self-hosted application
- Application domain: `baanbow.online` path `admin`
- เพิ่ม path `admin` ของ `www.baanbow.online` ด้วย
- Policy: Allow → Emails → อีเมลของคุณ

อย่าใส่ `/webhook` กับ `/d/*` เข้า Access เด็ดขาด — LINE กับลูกค้าจะเข้าไม่ได้

### 8. ตั้งเลขเริ่มต้นของเอกสาร (ถ้าต้องการ)

เลขรันเริ่มที่ 1 โดยอัตโนมัติ ถ้าเคยออกเอกสารมาก่อนแล้วอยากให้เดินต่อจากของเดิม ตั้งค่าในตาราง `counters` — ใส่ **เลขใบล่าสุดที่ออกไปแล้ว** ใบถัดไปจะเป็นเลขนั้น +1

```bash
npx wrangler d1 execute baanbow-office --remote --command "UPDATE counters SET n=120 WHERE key='quotation'"
```

key ที่ใช้ได้: `quotation` `receipt` `tax_invoice` `receipt_tax_invoice`

### 9. ใส่วันหยุดประจำปี

สั่งจาก LINE ได้เลย (`เพิ่มวันหยุด 31 ธันวาคม สิ้นปี`) หรือใส่ทีเดียวหลายวัน:

```bash
npx wrangler d1 execute baanbow-office --remote --command "INSERT OR REPLACE INTO holidays(date,name) VALUES ('2027-01-01','วันขึ้นปีใหม่'),('2027-04-13','สงกรานต์')"
```

วันหยุดใช้เตือนตอนตั้งกำหนดส่งงานว่าตรงวันหยุดหรือเสาร์-อาทิตย์

**เรื่อง VAT** — ถ้าไม่พิมพ์ว่า "รวม vat" / "ไม่รวม vat" / "ไม่มี vat" บอทจะถามกลับเสมอ ไม่เดาให้
ใบกำกับภาษี (TI) และใบเสร็จ/ใบกำกับภาษี (RT) บังคับมี VAT 7% ตอบ "ไม่มี vat" ไม่ได้

**หัก ณ ที่จ่าย** — พิมพ์ "หัก ณ ที่จ่าย 3%" ต่อท้าย รับเฉพาะ 1% กับ 3% ไม่พูดถึง = ไม่มี และไม่ขึ้นบนเอกสาร

## ผู้ขาย 2 บริษัท

เลือกได้ทีละบิลว่าออกเอกสารในนามไหน ข้อมูลอยู่ใน `SELLERS` ของ [src/config.js](src/config.js)

| key | ชื่อบนเอกสาร | เลขผู้เสียภาษี | ออกใบกำกับภาษีได้ |
|---|---|---|---|
| `tuaklang` | บริษัท ตัวกลาง จำกัด (สำนักงานใหญ่) | 0-4355-69001-41-3 | ✅ |
| `baanbow` | BAANBOW | — | ❌ |

- **สั่งจาก LINE** พิมพ์ต่อท้ายได้เลย เช่น `ทำใบเสนอราคา ... ในนามบ้านโบว์` หรือ `ในนามบริษัทตัวกลาง`
- **ไม่ระบุ** = ใช้ `tuaklang` (ค่าใน `DEFAULT_SELLER`) เอกสารเก่าทุกใบเป็นตัวนี้
- **BAANBOW ไม่มีเลขประจำตัวผู้เสียภาษี** จึงออกใบกำกับภาษี (TI) และใบเสร็จ/ใบกำกับภาษี (RT) ไม่ได้
  บอทจะปฏิเสธพร้อมบอกทางเลือกให้ ออกใบเสนอราคากับใบเสร็จรับเงินได้ตามปกติ
  ถ้าภายหลังจดทะเบียนแล้ว ใส่เลขลงช่อง `tax_id` ของ `baanbow` ใน `config.js` แล้ว deploy ใหม่ จบ
- **หัวกระดาษปรับตามบริษัทอัตโนมัติ** — มีเลขภาษีก็ขึ้นบรรทัดเลขภาษี มีอีเมลก็ขึ้นอีเมล
  โลโก้ ท้ายกระดาษ และบัญชีรับเงินใช้ร่วมกันทั้งสองบริษัท (`BRAND` กับ `PAYMENT`)
- **เลขรันเอกสารไม่แยกตามบริษัท** โดยตั้งใจ — เลขที่จึงไม่ซ้ำกันทั้งระบบ ไม่ว่าออกในนามไหน
- **สรุปยอดแยกตามบริษัทเสมอ** ทั้งใน LINE และหน้า `/admin` เพราะเป็นคนละนิติบุคคล ยื่น VAT คนละชุด

เพิ่มบริษัทที่สามภายหลังก็แค่เพิ่ม key ใน `SELLERS` ไม่ต้องแก้ migration หรือโค้ดส่วนอื่น

## งาน

**ไม่เปิดงานอัตโนมัติจากเอกสาร** โดยตั้งใจ — ใบเสนอราคาส่งไปหลายใบ แต่ลูกค้าตกลงจริงไม่กี่ใบ
ถ้าเปิดงานทุกใบจะมีงานค้างเปล่าๆ เต็มระบบ เจ้าของจึงเป็นคนสั่งเปิดเองเมื่อลูกค้าโอนแล้ว

```
เปิดงานจาก QT191069005
```

ดึงชื่อลูกค้า ยอดเงิน และผูก `doc_no` ให้อัตโนมัติ ตั้งชื่องานเองก็ได้โดยพิมพ์ต่อท้าย
เปิดจากใบเดิมซ้ำไม่ได้ บอทจะบอกว่าเปิดเป็นงานเลขอะไรไปแล้ว

งานที่ไม่ได้มาจากเอกสาร (เช่น งานที่ตกลงกันปากเปล่า) ใช้ `เพิ่มงาน <ชื่องาน>` ได้ตามปกติ

**กำหนดส่งเริ่มต้น 4 วัน** ถ้าไม่ได้ระบุ (`JOB_DEFAULT_DUE_DAYS` ใน config.js)
นับตามปฏิทิน ไม่ข้ามเสาร์-อาทิตย์ให้ แต่จะเตือนถ้ากำหนดส่งตรงวันหยุดหรือเสาร์-อาทิตย์

**แจ้งเตือน 2 รอบต่อวัน** — ไม่มีงานค้างก็ไม่ส่ง ไม่รบกวนเปล่า

| เวลาไทย | cron (UTC) | ส่งอะไร |
|---|---|---|
| 08:00 | `0 1 * * *` | งานเลยกำหนด / ครบวันนี้ / ครบพรุ่งนี้ — วางแผนวันนี้ |
| 17:00 | `0 10 * * *` | งานค้างทั้งหมด — ปิดงานที่เสร็จแล้วก่อนเลิกงาน |

แก้เวลาต้องแก้ 2 ที่ให้ตรงกัน: `crons` ใน `wrangler.toml` และ `CRON_MORNING`/`CRON_EVENING` ใน `src/config.js`
เพราะโค้ดใช้ค่าใน config เทียบว่า cron ที่ยิงมาเป็นรอบเช้าหรือรอบเย็น

## สต๊อก

**นับเป็นชิ้นเฉพาะโบว์สำเร็จรูป** ไม่ทำสต๊อกผ้า/ริบบิ้นเป็นม้วน
รับเข้าครั้งแรกตั้งรายการให้เอง ไม่ต้องสร้างสินค้าไว้ก่อน

**ต้นทุนกับราคาขายตั้งย้อนหลังได้** โดยไม่แตะจำนวน (`โบว์ทอง ทุน 45 ขาย 99`)
ส่งมาช่องเดียวอีกช่องเก็บค่าเดิมไว้ และ**ตั้งได้เฉพาะของที่มีรายการแล้ว** —
พิมพ์ชื่อผิดจะได้ไม่เกิดรายการผีที่ไม่มีของจริง ต่างจากรับเข้าที่สร้างให้เอง

**ยอดคงเหลือคิดจาก `SUM(delta)` ของตาราง `stock_moves`** ไม่ได้เก็บเป็นตัวเลขเดียวที่เขียนทับ
ช้ากว่าเล็กน้อยแต่ยอดไม่เคยเพี้ยน และย้อนดูได้ว่าของหายตอนไหน
ห้ามลบแถว ลงผิดให้ลงแถวใหม่เป็น `ปรับยอด` เหมือนเอกสารที่ยกเลิกแต่ไม่ลบ

**ตัดสต๊อกตอน "ส่งของ" เท่านั้น** (`STOCK_CUT_ON`) ไม่ตัดตอนออกใบเสนอราคาหรือตอนลูกค้าโอน
เพราะใบเสนอราคาส่งไปหลายใบแต่ตกลงจริงไม่กี่ใบ ถ้าตัดตอนนั้นยอดจะเพี้ยนตลอด

```
ส่งของงาน 7
```

อ่านรายการจากบิลที่งานนั้นผูกอยู่ แล้วจับคู่ชื่อรายการกับสินค้าในสต๊อกด้วย `name_key`
**จับคู่ไม่ได้จะบอกว่าตัวไหนไม่ได้ตัด ไม่เดาและไม่ตัดมั่ว** · งานที่ตัดไปแล้วตัดซ้ำไม่ได้ (เช็คจาก `job_id`)
งานที่ไม่ได้ผูกเอกสารต้องปรับยอดเอง เพราะระบบไม่รู้ว่าส่งอะไรไปเท่าไร

**ยอดติดลบได้ แต่เตือนทุกครั้ง** (`STOCK_ALLOW_NEGATIVE`) ร้านส่งของก่อนลงรับเข้าเป็นเรื่องปกติ
ถ้าบล็อกไว้เจ้าของจะเลิกบันทึก แล้วระบบจะไม่มีข้อมูลเลย ซึ่งแย่กว่ายอดติดลบ

## รายรับรายจ่าย

**รายจ่าย 4 หมวด** (`EXPENSE_CATEGORIES`) — ค่าวัสดุ · ค่าส่ง · ค่าแรง · อื่นๆ
อ่านไม่เข้าข้อไหนเข้า "อื่นๆ" ไม่ทิ้งรายการ แล้วบอกให้รู้ว่าเข้าหมวดไหนไป
ผูกกับงานได้ถ้าเป็นค่าใช้จ่ายของงานนั้นโดยตรง และแยกได้ว่าจ่ายในนามบริษัทไหน

**รายรับไม่มีตารางของตัวเอง** โดยตั้งใจ — ดึงจาก `documents` ที่ `status='issued'` ตรงๆ
ไม่งั้นยอดขายจะมี 2 แหล่งที่ไม่ตรงกัน แล้วไม่รู้ว่าจะเชื่ออันไหน
`สรุปเดือนนี้` จึงเป็น รายรับจากเอกสาร − รายจ่าย และยังแยกยอดตามบริษัทเหมือนเดิม

## แท็บสรุปใน /admin

เป็นแดชบอร์ด: ตัวเลขกำไรตัวใหญ่ → กราฟรายรับเทียบรายจ่าย 6 เดือน → รายจ่ายแยกหมวด
→ รายรับแยกบริษัท → ตัวเลขงานกับสต๊อก → ตารางแยก VAT รายบริษัท (ไว้ใช้ยื่นภาษี)

**กราฟวาดเป็น SVG จากฝั่งเซิร์ฟเวอร์ใน `src/chart.js`** ไม่มี JS ไม่มีไลบรารีจาก CDN
เปิดบนมือถือเน็ตช้าก็ขึ้นพร้อมหน้า และกราฟไม่ใช่ทางเดียวที่จะอ่านค่า —
กราฟ 6 เดือนมีตาราง "ดูเป็นตัวเลข" กางได้ (`<details>` ของ HTML เอง) กราฟแท่งนอนติดตัวเลขที่ปลายแท่ง

กติกาที่ยึดตอนทำกราฟ เผื่อแก้ทีหลัง:

- **สีข้อมูลแยกจากสีแบรนด์** รายรับน้ำเงิน `#2a78d6` รายจ่ายส้ม `#eb6834` ผ่านเครื่องตรวจตาบอดสีบนพื้นขาว
  ห้ามเอาสีไวน์มาใช้กับข้อมูล เพราะในหน้านี้สีไวน์แปลว่า "เลยกำหนด/ติดลบ" ไปแล้ว
- **หมวดรายจ่ายใช้สีเดียวกันทุกแท่ง** ไม่ไล่เข้มตามยอด เพราะความยาวแท่งบอกยอดอยู่แล้ว
- **ติดป้ายตัวเลขเฉพาะเดือนล่าสุด และเฉพาะแท่งที่สูงกว่า** ติดทั้งคู่แล้วป้ายทับกันตอนยอดใกล้กัน
- **เดือนที่ไม่มีรายการต้องเป็นแท่ง 0 ไม่ใช่หายไป** ไม่งั้นแกนเวลาจะโกหก
- **`main` กว้างไม่เกิน 480px** เพราะ SVG กว้าง 100% บนจอคอมจะขยายจนตัวอักษรในกราฟใหญ่กว่าหัวข้อ

## กฎที่เขียนไว้ในโค้ด

- **เงินเป็นสตางค์ (integer) ทุกจุด** AI ไม่เคยคิดเลข ทุกยอดคำนวณใน `src/money.js`
- **เลขที่เอกสาร** = คำนำหน้า + `ddmmyy` (พ.ศ. 2 หลัก) + เลขรัน 3 หลัก
  เลขรัน **ต่อเนื่องตลอด แยกตามประเภท ไม่รีเซ็ตรายวัน** และออกด้วย SQL คำสั่งเดียวแบบ atomic ตอนพิมพ์ "ยืนยัน" เท่านั้น
  เกิน 999 แล้วเลขจะยาวขึ้นเอง ไม่ตัดหลักทิ้ง เลขจึงไม่ซ้ำตลอดอายุระบบ
- **ไม่มีคำสั่งลบเอกสาร** ยกเลิกได้อย่างเดียว (`status='void'`) เลขที่ที่ใช้แล้วไม่ถูกนำกลับมาใช้ซ้ำ
- **ลูกค้า** บันทึกอัตโนมัติ ออกบิลครั้งถัดไปพิมพ์แค่ชื่อ ที่อยู่/เลขภาษี/สาขา จะถูกดึงมาเติมเอง
  ข้อมูลลูกค้าบนเอกสารเก่าเป็นสำเนา ณ วันออก แก้ที่อยู่วันนี้ไม่กระทบเอกสารที่ออกไปแล้ว
- **เวลา Asia/Bangkok เสมอ** ไม่ขึ้นกับเวลาของเครื่องที่รัน (Worker รันที่ UTC)
- **รายการที่รอยืนยันหมดอายุ 15 นาที** และอ่านแล้วลบทันที กดยืนยันซ้ำไม่ได้เอกสารสองใบ

`src/render.js` สร้างหน้าจากแม่แบบที่อนุมัติแล้ว `baanbow-doc-a4.html` — class และโครงสร้างตรงกันทั้งหมด

- ปุ่มสลับประเภทเอกสารกับปุ่มลายน้ำในแม่แบบเป็นของไว้พรีวิว ตัดออกแล้ว เพราะเอกสารจริงประเภทเดียวสถานะเดียวตายตัวตอน render

## เว็บเดิม deploy ยังไง (บันทึกไว้กันลืม)

- เว็บ `baanbow.online` คือ Worker ชื่อ **`baan-bow-website`** แบบ static assets ไม่ใช่ Cloudflare Pages
- **ไม่ได้ต่อกับ GitHub** — `main` บน GitHub มีแค่ 3 ไฟล์ ค้างไว้ตั้งแต่ก่อนรีดีไซน์ ส่วนเว็บจริงอัปตรงจากเครื่อง
  แปลว่า `git push` ไม่มีผลกับเว็บที่ขึ้นอยู่เลย และ `wrangler deploy` ของ Worker ตัวนี้ก็ไม่เกี่ยวกับ git เช่นกัน
- เว็บเสิร์ฟ **ทั้งโฟลเดอร์** เป็นไฟล์ static (ลองดู `https://www.baanbow.online/.gitignore` โหลดได้จริง)
  จึงมีไฟล์ [`.assetsignore`](../.assetsignore) ที่โฟลเดอร์แม่ กัน `worker/`, `node_modules/` และไฟล์อื่น
  ไม่ให้ถูกอัปขึ้นตอน deploy เว็บ **อย่าลบไฟล์นั้น** ไม่งั้นโค้ดฝั่งเซิร์ฟเวอร์จะเปิดอ่านได้จากเน็ต

## หมายเหตุ

- Cron `0 1 * * *` = 01:00 UTC = **08:00 น. เวลาไทย** Cloudflare รับ cron เป็น UTC เท่านั้น
- รูปแบบใบกำกับภาษีเป็นร่างตามข้อมูลที่ต้องมีโดยทั่วไป **ให้นักบัญชีตรวจก่อนใช้จริง**
- `/d/:token` ตั้ง `noindex` ไว้แล้ว และ token สุ่ม 128 บิต แต่ใครได้ลิงก์ไปก็เปิดดูได้ — ส่งให้เฉพาะลูกค้าเจ้าของบิล
